# Compose 适配场景矩阵

## 读取时机

当任务涉及 Compose 页面实现、页面修复、复杂列表、弹窗、横屏/平板/折叠屏、多窗口、键盘、RTL、深色模式、字体放大或无障碍时，读取本文件。目标是把适配风险转成具体 Compose 布局决策，而不是只对齐一张默认设备截图。

## 窗口和设备形态

- 窗口尺寸：手机小屏、常规屏、大屏、横屏、平板、ChromeOS、外接显示器、分屏、多窗口、自由窗口都会改变可用宽高；布局分支优先基于实际 constraints、window size class 或项目封装，不基于设备型号。
- 折叠屏：折痕、铰链、半折叠姿态、双屏区域和展开/折叠切换会改变内容连续性；关键按钮、输入框、弹窗、底部栏不能跨不可用区域或被折痕切开。
- 方向切换：横竖屏切换后要验证 `rememberSaveable` 状态、Lazy 滚动位置、分页状态、输入焦点、弹窗和底部栏位置。
- 大屏布局：宽屏不要简单拉伸手机布局；必要时改为双栏、列表详情、导航 rail、网格列数增加或内容最大宽度居中。
- 小屏布局：320dp/360dp 宽下优先保证主任务可完成，低优先级标签、辅助按钮、说明文可折叠、换行或隐藏。

## WindowInsets 和系统区域

- edge-to-edge：状态栏、导航栏、手势区域、刘海/挖孔、透明系统栏要用 `WindowInsets` 明确处理；可点击元素必须避开系统栏和手势热区。
- Compose API：优先用项目既有 inset 封装；没有封装时再使用 `Modifier.windowInsetsPadding`、`statusBarsPadding`、`navigationBarsPadding`、`imePadding`、`safeDrawingPadding` 等。
- 底部固定元素：吸底按钮、底部操作栏、FAB、Snackbar、BottomSheet 要同时处理导航栏、手势区域和键盘。
- 顶部固定元素：沉浸式标题栏、吸顶 tab、搜索栏、banner 顶图要明确是绘制到状态栏下面，还是延伸到状态栏背后。
- 弹层：Dialog、Popup、DropdownMenu、Tooltip、引导浮层、BottomSheet 要处理锚点越界、小屏超高、横屏、键盘和系统栏遮挡。

## 键盘和输入

- 表单、搜索、评论、登录、弹窗输入、底部输入栏要验证键盘弹起后的可见区域、焦点滚动、提交按钮、错误提示、候选词栏和系统导航栏。
- 输入框要明确单行/多行、最大高度、内部滚动、计数器、清除按钮、密码可见按钮、helper text 和 error text 的占位策略。
- Compose 中不要只依赖初始布局；键盘出现会改变 insets，`imePadding`、滚动容器和焦点 bring-into-view 要配合使用。

## 字体、显示大小和文本系统

- 验证 font scale 1.15/1.3，触及通用组件时考虑更大字体；按钮、标签、输入框、顶部栏和底部栏不能裁字。
- 系统显示大小、粗体文本、不同系统字体、fallback font、emoji、数字等宽/非等宽都会影响测量；不要用固定高度假设文本永远一行。
- `Text` 的 `maxLines`、`overflow`、`softWrap`、`lineHeight`、`includeFontPadding` 相关项目约定要明确。
- 富文本、可点击 span、混排图标、价格、小数、倒计时、日期、单位要用最长合理样例验证。

## 本地化、RTL 和资源

- 本地化会影响字符串长度、断行、货币、日期、复数、单位和图片文字；按钮和标签尤其要预留文本扩展空间。
- RTL 下要检查返回箭头、方向图标、进度、列表滑动方向、Row 排列、padding start/end、文本对齐和动画方向是否需要镜像。
- 资源必须有默认兜底：`drawable`、`mipmap`、`values`、`font`、`night`、`sw<N>dp`、`land`、语言资源不能只存在限定目录。
- 带文字图片要确认是否需要本地化替换；如果不替换，至少保证布局不会因不同语言资源缺失而崩溃。

## 主题、颜色和渲染

- 深色模式、高对比度、省电模式、动态主题色、透明系统栏、品牌换肤会影响颜色、阴影、分割线和系统栏图标明暗。
- ldpi 到 xxxhdpi、不同 GPU/系统版本、圆角抗锯齿、阴影、1dp/1px 分割线、矢量 viewport、图片采样可能产生视觉偏差。
- Compose 中 `clip`、`background`、`border`、`shadow`、`drawBehind`、`graphicsLayer` 的顺序会影响圆角、阴影和裁剪结果；按设计稿顺序实现。

## 内容和状态

- 覆盖加载中、空态、错误态、无权限、未登录、审核中、禁用、过期、下架、删除、弱网、分页无更多、局部刷新失败。
- 数据极值包括 0、1、多条、超长列表、重复数据、缺字段、空字符串、emoji、换行符、富文本、超大数字、负数、极短/极长昵称、图片宽高缺失。
- 交互状态包括按下、选中、禁用、加载、倒计时、防重复点击、滑动、拖拽、吸顶、展开收起、动画中断、返回恢复。
- 可访问性要检查 TalkBack 焦点顺序、触控热区、contentDescription、合并朗读、禁用态可理解、颜色对比度和可缩放内容。

## Lazy、滚动和分页

- `LazyColumn`、`LazyRow`、`LazyVerticalGrid`、瀑布流、Pager、FlowRow、吸顶 header、下拉刷新、分页 footer 叠加时，要确认滚动范围、嵌套滚动和边缘留白。
- Lazy item 使用稳定 key；动态高度、图片加载、展开收起、局部刷新不能导致错误复用、状态串位或明显滚动跳动。
- 网格列数基于可用宽度和最小 item 宽度计算；`GridCells.Adaptive` 优先于固定列数，除非设计明确固定。
- 分页列表要覆盖首屏不足一屏、加载更多失败、无更多、刷新中、删除 item、插入 item、图片迟到后的高度变化。

## 媒体和裁剪

- 静态图、动图、视频封面、直播流、透明 PNG、长图、宽图、二维码、头像、带文字图片要分别确认比例、裁剪、圆角、背景和加载失败。
- 圆角卡片、阴影、描边、父子裁剪、列表首尾 item、瀑布流边缘要检查是否误裁、露底或阴影被裁。
- 图片加载前后容器尺寸必须稳定；占位图、失败图、真实图使用同一比例和裁剪策略，避免视觉跳动。

## 性能边界

- 动态测量、`onSizeChanged`、`SubcomposeLayout`、`TextMeasurer`、富文本、图片圆角/模糊、瀑布流和复杂约束不要为了适配引入明显卡顿。
- 能用父级 constraints 和标准布局表达时，不要在 composition 阶段读取屏幕宽度后手算所有尺寸。
- 避免在 Lazy item 中创建不稳定对象、重复执行重计算或因图片状态变化触发整屏重组。
