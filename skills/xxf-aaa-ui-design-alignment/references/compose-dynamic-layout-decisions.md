# Compose 动态布局决策

## 读取时机

实现文本、图片、按钮、标签、输入框、卡片、Lazy item、弹窗、底部栏等会受内容或窗口约束影响的 Compose 组件时，读取本文件。目标是先做布局决策，再写 modifier，避免用固定宽高碰运气。

## 通用决策顺序

1. 判断尺寸来源：设计稿固定值、父容器 constraints、内容自然尺寸、窗口尺寸、服务端字段、图片真实比例或业务比例。
2. 判断是否允许变化：宽度可变、高度可变、比例固定、最大/最小边界、可滚动、可折叠、可隐藏。
3. 判断冲突优先级：谁必须展示、谁可压缩、谁可截断、谁可换行、谁可隐藏、谁移动到下一行。
4. 判断状态集合：默认、加载、空、错误、缺字段、长文案、字体放大、RTL、深色模式、键盘、横屏/宽屏。
5. 再选择 Compose API：`Row/Column/Box`、`Lazy*`、`FlowRow`、`BoxWithConstraints`、`ConstraintLayout`、`SubcomposeLayout` 或项目组件。

## 外层容器

- 外层容器不要默认固定高度。只要内部文本、标签、图片、按钮、错误提示或状态区可能变化，就要允许 `wrapContentHeight`、滚动、折叠或最大高度。
- 固定宽高只用于头像、图标、明确业务比例的封面、设计强约束按钮等；固定前要能说出业务前提。
- 需要视觉最小尺寸时用 `defaultMinSize`、`heightIn`、`widthIn`；需要强制尺寸时才用 `requiredSize`。
- 页面级容器要区分内容 padding、系统 inset padding、列表 contentPadding 和视觉背景 padding，避免重复叠加。
- 宽屏下如果内容不应无限拉伸，用 `widthIn(max = ...)` 或项目的 max content width 居中承接。

## Row 横向组合

- 先固定头像、图标、右侧按钮、价格、角标等不可压缩元素；中间文本用 `Modifier.weight(1f, fill = false)` 或 `fill = true` 承接剩余空间。
- 长标题、昵称、商品名、说明文默认不能假设单行；如果必须单行，设置 `maxLines = 1` 和 `overflow = TextOverflow.Ellipsis`。
- 价格、倒计时、状态标签、按钮文案要按最长合理样例验证；必要时让低优先级标签隐藏或换行，而不是挤掉主标题。
- 多个标签横排时优先考虑 `FlowRow`、最大行数或折叠策略；不要让一串 `Row` 子项无限挤压。
- 图标加文本按钮要保证文字放大后不裁字；空间不足时优先改成纯图标按钮、更多菜单或换行布局。

## Column 纵向组合

- 多行文本、错误提示、富文本、标签区、图片区增高时，父级应跟随增高或提供滚动。
- 吸底按钮和内容列表共存时，列表使用明确 bottom padding，避免最后一项被按钮遮挡。
- 内容不足一屏和超过一屏都要验证：不足一屏时空态/按钮位置合理，超过一屏时底部内容可滚到。
- 标题栏、tab、筛选栏、分页 footer、Snackbar、BottomSheet 同时存在时，检查垂直空间冲突。

## Text

- 每个动态 `Text` 都要明确宽度策略、`maxLines`、`overflow`、`softWrap`、`lineHeight` 和对齐方式。
- 单行适合标题栏、按钮、短标签、金额、状态短文案；用户名、昵称、商品名、活动标题、说明文、错误提示、协议文案默认不能假设永远单行。
- 多行文本要处理行高、段落间距、末行按钮/标签挤压、父容器动态高度和 Lazy item 高度变化。
- 对价格、数字、日期、倒计时、单位、富文本、emoji、换行符、英文长词和无空格长串使用极值样例。
- 需要测量文本时优先让布局系统处理；只有确实需要预判截断、对齐或自定义绘制时才使用 `TextMeasurer`，并注意缓存和重组成本。

## Image

- 图片必须明确容器尺寸、业务比例、占位比例、失败态比例和 `ContentScale`。
- 头像、图标、角标优先固定容器尺寸，图片内容按规则裁剪或内边距适配。
- 商品图、封面图、banner、详情图优先按业务比例和可用宽度确定高度，通常用 `Modifier.aspectRatio` 保持加载前后稳定。
- 远程图片不能依赖原图刚好符合设计稿比例；统一裁剪、留白、背景色、圆角和失败兜底。
- 动图、视频封面、透明 PNG、长图、宽图、二维码、带文字图片要分别确认是否可裁剪；二维码和带文字图片通常不能 `Crop` 到缺内容。
- 图片圆角、阴影、描边注意 modifier 顺序：通常先尺寸，再阴影/背景/裁剪/边框/图片内容，按项目视觉约定实现。

## Button、Chip、Badge

- 文案可变时设置最小宽度和水平 padding；宽度不可动态时设置截断、图标化或降级菜单策略。
- 标签、气泡、角标要考虑数字变多、99+、多语言、字体放大和 RTL。
- 倒计时按钮、加载按钮、防重复点击按钮要保证状态切换时宽高稳定，不因文本变化导致相邻元素跳动。
- 禁用、选中、按下、加载态不仅颜色要对齐，也要保证触控热区和内容描述合理。

## TextField 和输入区域

- 明确单行/多行、最大高度、内部滚动、键盘 ime padding、焦点 bring-into-view、错误提示、helper text、计数字段和清除按钮。
- 多行输入框不要无限撑高页面；设置最大高度或让内部可滚动。
- 底部输入栏要同时处理键盘、导航栏、横屏、小屏和内容列表 bottom padding。

## Lazy item

- item 不依赖父页面固定高度；0/1/少量/大量数据都要可用。
- 动态高度 item 使用稳定 key，展开状态、输入状态、图片加载状态不要串到其他 item。
- 图片加载前后 item 高度要稳定；瀑布流可变高度必须基于已知比例或缓存测量结果。
- 局部刷新、删除、插入、分页、空态和错误态要保持滚动位置可预期。

## 弹窗、半屏页和浮层

- Dialog、BottomSheet、Popup、DropdownMenu、Tooltip、Snackbar、引导浮层要设置最大宽高、可滚动内容区和系统 inset 避让。
- 锚点菜单要处理屏幕边缘越界；底部 sheet 要处理键盘弹起和内容超高。
- 弹窗内按钮和输入框不能因为字体放大或横屏高度不足被裁掉。

## 何时使用高级布局

- `BoxWithConstraints`：需要根据父级可用宽高选择布局或列数时使用；不要只为读取屏幕宽度而使用。
- `ConstraintLayout`：复杂相对定位、baseline 对齐、多元素互相约束时使用；简单 Row/Column 能表达时不要引入。
- `SubcomposeLayout`：确实需要先测量一部分内容再决定另一部分布局时使用；注意性能，尤其不要滥用于 Lazy item。
- `onSizeChanged`/`onGloballyPositioned`：只用于确实需要上报尺寸、动画或锚点定位的场景；不要把它作为常规布局计算入口。
