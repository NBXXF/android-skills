# aaaaa-xxf-requirements-checklist — 触发用例

## 应该触发

- "对齐一下需求" / "需求对齐"
- "核查这个需求哪些没做到" / "检查哪些漏了"
- "实现核查" / "核对实现" / "对照需求文档检查一遍"
- "这个需求落地了吗，差在哪里"
- "整理一份问题清单" / "把剩余问题列成表格"
- "清单还剩什么" / "剩余问题收敛一下"
- "更新核查文档" / "核查文档同步一下"
- "按编号继续" / "处理第 3 项" / "003 已解决，移掉吧"
- "继续上一轮的问题清单" / "接着上次核查的来"
- "哪些待澄清" / "哪些缺结论" / "哪些还不确定"
- "哪些缺资源" / "还缺什么资料" / "要谁提供什么"
- "哪些还要验证" / "待验证项过一遍"
- 贴出需求文档 / plan / 设计稿链接后问 "我们做到哪了"
- "联调 / 提测 / 上线前把剩余问题收敛一下"
- "第 2 项我确认了，按这个来"
- "002 选 A，第 3 项砍了"（一轮批量答复速记）
- 贴截图 / 日志 / 录屏说 "第 2 项你看，好了"
- "这个清单文件在哪 / 叫什么名字"

## 不应该触发

- "这里用方案 A 还是方案 B" → 单点技术选型，走 `aaaaa-xxf-clarify-question`，尚未形成清单诉求
- "把这个按钮改成圆角、间距改 8dp" → 纯视觉对稿，走 `aaaaa-xxf-ui-design-alignment`
- "帮我实现 XX 功能" / "修一下这个 bug" → 直接交付任务，走 `aaaaa-xxf-delivery-loop`；完成后需要核查再进入本 skill
- "review 一下这次改动" → 走 `aaaaa-xxf-code-reviewer`，本 skill 只在审查结论需要入清单时参与
- "跑一下最小验证" / "补个单测" → 走 `aaaaa-xxf-test-strategy` / `aaaaa-xxf-auto-test-orchestrator`
- "打个 release 包" → 走 `aaaaa-xxf-android-package-builder`

## 边界用例

- "对齐需求，确定的没做到就补齐"
  - 期望：触发。核查 + 授权修复；确定问题直接实现并验证，待澄清项仍先提问。
- "对齐需求，先别改代码"
  - 期望：触发。只核查；确定问题只给处理方向，不动业务代码。
- "第 2 项好了"
  - 期望：触发（确认轮）。先按该行验收标准做最小核验，通过才删行；不直接信口头完成。
- "就按方案 B 吧"（针对某待澄清项）
  - 期望：触发（答复轮）。先把决策记入 `vibe-coding-clarify.md`，再按原编号转入实现；已有结论 ≠ 已经完成。
- "资料我发你了"（对应某缺资源项）
  - 期望：触发（资源轮）。只解除依赖；还需接入或验证的按原编号转入对应表，不因"资料到了"整项删除。
- "这期先不做第 5 项"
  - 期望：触发。暂缓：保留行并注明暂缓，不能记为完成。
- "第 5 项砍了 / 移出本期"
  - 期望：触发。明确取消：删行并在清单头"范围与授权"注明，不宣称已实现。
- "全部对齐了吗"
  - 期望：触发。按四表剩余数量与阻塞点如实回答，未解决项不能用"全部对齐"概括。
- "继续"（存在未决澄清项时）
  - 期望：触发但不当作答复。"继续"不等于选定某个未决方案；未决项保持未决，继续其余已授权工作。
- "昨天那个问题清单继续"（新会话 / 重启后）
  - 期望：触发。先读清单文件 + 决策记录恢复上下文，不重新询问已确认项。
- "帮我把 003 拆成两个"
  - 期望：触发。保留原编号作其中一项，其余用新号并注明来源。
- "设计稿上这个控件是不是多余的"
  - 期望：触发。先核对完整源设计与后续指示；不能仅凭旧文档截图断言多做了。
- "服务端这个接口做了没"
  - 期望：触发但先查契约。已有明确契约且客户端已接入的不算未实现；真实结果未知只保留必要的联调验收项。
- "清单里再加一条"
  - 期望：触发。新条目用新的跨表唯一编号；不复活、不复用已删除编号。
- "都按建议来 / 按你说的办"
  - 期望：触发。该批待澄清项全部采用建议项，决策记录注明"用户采用助手建议"，再按原编号转实现。
- 贴截图 / 日志说 "第 2 项好了"
  - 期望：触发（确认轮）。截图 / 日志是有效证据，在行内注明来源与日期；仍对照该行验收标准判断是否达删行级别，不足则转待验证表。
- "这个需求点不用做了，用户拍板了"
  - 期望：触发。新证据/明确决策覆盖 → 删行，并在本轮回复简述撤销依据。
