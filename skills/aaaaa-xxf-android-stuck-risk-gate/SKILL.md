# 卡死/堵死风险门禁（Stuck Risk Gate）

## 为什么是灾难性问题

这类问题不崩溃、无报错 UI，只表现为**静默的功能失效或资源烧穿**：后台链路停止推进（上报不再到达、
任务不再完成）、用户被永久卡在某个状态、CPU/电量被死循环烧干、或某条业务路径永远走不到。
发现滞后（往往数天后从数据缺口倒查）且常无法补录。实装案例：

- 队列堵死（2026-11，OverseaReels 达标上报队列）：严格 FIFO 冲队 + 队头一条持续失败 → 后面全部
  记录被无限期阻塞，唯一出口是攒满 50 条把队头挤出。修正：失败轮转队尾 + 按入队时间淘汰。
- 自动链路成环（OverseaReels 解锁失败回退）：解锁广告失败回退到上一可播集，若回退集已看完会
  自动连播又触发解锁 → 成环。修正：lastAutoAdvanceFrom 标记打破环路。
- 测试自身卡死（2026-11）：挂起 await 的协程是 runBlocking 子协程，测试永不结束。

## 结论等级

- Pass：每条推进链路都有终局出口与环路打破点，单条失败不阻塞其余，退避策略有依据或已澄清。
- Warn：主链路有出口，但存在有限残余（如依赖服务端尚未定案的窗口规则），已记录跟踪项。
- Block：存在可无限重试且阻塞后续的条目、无封顶淘汰、无出口的状态/循环、或退避策略缺失且未澄清就上线。

## 形态识别（先分类再套条款）

| 形态 | 典型代码 | 核心风险 |
|---|---|---|
| A. 持久化多条队列 + 串行消费（最高危） | MMKV/DB 待上报 List + drain 循环 | 队头阻塞、毒丸无限重试、封顶挤出健康记录 |
| B. 退避重试（单条/单值） | retry + delay 循环 | 无上限重试、未知错误码当可重试 |
| C. 锁/Mutex/队列化初始化 | Mutex、单例懒加载排队、一次性 init、在途占位 Deferred | 持锁异常不放锁、init/占位失败后等待方永久挂起、互相等待 |
| D. 逻辑死循环 | while(true)、相互递归、自动重试链 | 循环体无进展仍继续、状态机两态互踢、自动流程回退成环 |
| E. 业务链路不可达 | 状态 gate、flag、深链路由 | flag 置位后无任何路径清掉、前置条件永假、入口被更早的 return 拦截 |
| F. 静默降级/消息丢失 | 配置解析失败走默认值、SharedFlow DROP_OLDEST、订阅晚到 | 功能静默关闭/事件丢失无日志，线上只表现为"功能没了" |
| G. 时钟依赖 | 墙钟做间隔/窗口/去重键 | 时钟回拨（用户改时间/NTP）窗口失效、间隔变负、去重键失效 |
| H. 无界增长 | 只增不减的 MMKV/内存 Map、无清理缓存 | 数月后体积/内存膨胀，序列化耗时拖慢主线程 |

**未知错误码处置矩阵**（B 形态核心，以 SHResponseData/subCode 体系为例）：已知且可展示 → 走本地文案；
明确业务拒绝/参数错 → DROP 不重试；结果未知（网络/超时/临时不可用）→ RETRY 但必须有上限或过期兜底；
**其余未知 code 一律视为结果未知处理，禁止默认丢弃也禁止无限重试**。

## 必查清单（新增/评审逐条过；A 形态走完全部，其余按形态套用）

1. **需求退避策略对齐**：需求/后端契约是否定义了——重试上限或窗口、退避节奏、幂等键、确定性失败
   （参数错/业务拒绝）如何处置、过期补报规则？
   - 需求没写或不完善 → **必须二选一**：技术层兜底（见 2-6）或 AskUserQuestion/需求澄清清单主动问，
     结论记入决策记录；**禁止静默按最顺手的口径上线**。
   - 后端"当前实现如此、产品未最终确认"的规则 → 客户端记待澄清项跟踪，先按现契约对齐。
2. **单条失败不阻塞整队**（A）：失败条目轮转队尾 / 每条独立游标与 nextAttemptAt / 跳过继续，三选一；
   严格 FIFO + 队头无限重试是 Block。
3. **每条有终局出口**（A/B）：成功移除、确定性失败丢弃（毒丸分类：参数错/明确业务拒绝 → DROP；
   仅结果未知 → RETRY）、封顶/过期淘汰，至少三者齐备。未知错误码默认不可无限 RETRY——长期 RETRY
   的毒丸等同卡死，必须有最大尝试次数或过期时间兜底。
4. **队列封顶与淘汰策略**（A）：上限明确；淘汰按**业务时间**（如入队时间）而非列表位置
   （轮转/重排会改变位置，按位置淘汰会挤出健康记录留下毒丸）。
5. **持久化与恢复**（A/B）：入队即落盘、重试保留原业务报文与原时间戳（幂等语义）、用户隔离交存储
   框架（如 USER_ONLY key+userId），业务层不自写切换特判。
6. **可观测**（全部）：入队/出队/丢弃/退避/打破环路均有日志（条目键、结果、尝试次数），真机可验证。
7. **锁与初始化**（C）：临界区内异常路径全部放锁（try/finally）；一次性初始化失败必须有重试入口或
   降级路径，禁止失败后所有 await 永久挂起；多把锁按固定顺序获取。
8. **死循环与环路**（D）：每个 while(true)/自动推进链路必须写明**退出条件与打破点**；"失败回退到
   前一状态"要验证回退目标不会再次自动进入失败流程（成环）；循环体必须每次有可度量的进展
   （位置/计数/时间），无进展即退避或终止。
9. **链路可达性**（E）：关键状态 gate 的**清除路径**与置位路径成对出现（对照枚举每个 flag 的
   set/clear 双向）；深层入口逐层核对前置条件不为永假；新增拦截 return 不吞掉后续必要流程。
10. **静默降级可观测**（F）：配置/缓存解析失败走默认值时必须留日志（含 key 与原因），不允许
    "解析失败=功能静默关闭"无痕发生；可丢失事件流（SharedFlow DROP_OLDEST）只能作观测通道，
    业务正确性必须由可重放的状态/快照承载，并在 KDoc 声明该契约。
11. **时钟口径**（G）：**间隔/窗口/节流用单调时钟**（elapsedRealtime），墙钟只用于绝对时间戳与
    展示；凡用墙钟做差值的地方必须 coerceAtLeast(0) 防回拨为负，跨天/归日逻辑优先用服务端返回的
    日期而不是本地推算。
12. **容量上界**（H）：持久化字典/内存缓存必须有清理时机或数量上界（如按日桶保留 N 天、LRU），
    并写明增长上界估算；无上界的"只增 map"是 Warn 起步。

## 正面范例（OverseaReels 已验证写法，可对照抄）

- 在途占位防挂起：CatalogDetailStore.fetch——CompletableDeferred 占位后，订阅成功/失败/构造期
  异常三条路径都 complete + remove，等待方永不悬挂。
- 事件流降级契约：VodPlaybackEvents——DROP_OLDEST 事件流 KDoc 明示"不是可靠消息队列"，
  正确性由 500ms 快照承载。
- 序列化守卫：DramaApiServiceTest.dtoFieldsDeclareSerializedNames——反射测试强制所有 DTO 字段
  带 @SerializedName，防 R8 混淆后 release-only 静默解析失败。
- 队列全出口：EpisodeQualifyService——失败轮转队尾 + enqueuedAt FIFO + 按入队时间封顶淘汰 +
  48h/200 次兜底淘汰 + 毒丸分类，五出口齐备。

## 必测用例（按形态，缺一不可）

- A 形态：1) 单条永久失败 → 后续条目仍被消费；2) 毒丸错误码 → 立即丢弃；3) 封顶 → 按业务时间淘汰
  最旧；4) 进程重启 → 队列恢复、原报文/时间戳不变；5) 挂起协程必须在测试收尾放行（防测试自身卡死）。
- D 形态：构造失败回退 → 回退目标不再自动触发原失败流程（环路打破断言）。
- E 形态：置位 gate → 走到清障路径 → 状态复位 → 链路恢复可达。

## 反模式（见一例 Block 一例）

- 严格 FIFO drain + 队头 KEEP_RETRY 无限等待；未知错误码一律 RETRY 且无上限/过期。
- `takeLast(N)` 按列表位置封顶，而消费过程会轮转/重排。
- 队列只在内存或失败后才落盘；退避 delay 卡住全局循环却不评估其余条目。
- Mutex 内 return/throw 不放锁；init 失败后 await 方永久挂起无重试入口。
- "失败就回退到上一步"，而上一步会自动再次进入失败流程（回退成环）。
- flag 只置不清；防御式 return 把唯一推进路径拦截成不可达；需求没写退避策略就默认无限重试/失败即丢。
- 配置解析失败静默走默认值无日志；业务正确性寄托在 DROP_OLDEST 事件流上。
- 间隔/节流/去重用墙钟做差值且不 clamp 负值；跨天归日靠本地时钟推算。
- 只增不减的持久化字典，无上界、无清理、无容量估算。
